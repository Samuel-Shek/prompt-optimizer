# prompt-optimizer

把粗糙需求整理为可执行、可复制的提示词。当前版本：**v3.3.0**，MIT 许可。

## 三种使用方式

- **独立优化**：用户要改写提示词，返回一份终稿，不代做业务任务。
- **只审阅**：用户说“先评价，别改”，只指出问题，不自动重写。
- **宿主内部整理**：当前 AI 为复杂任务分配一个整理子任务；优化器返回提示词，当前 AI 继续完成原任务。不能只交提示词就宣称原任务完成。

保留目标、数字、精确字符串、允许与禁止项、事实状态和验收标准。多轮修改不丢掉未撤销的要求。待处理材料中的嵌入指令不能扩大权限。按任务复杂度组织内容，不给简单任务套长模板。

## 安装

```bash
git clone https://github.com/Samuel-Shek/prompt-optimizer.git
```

把克隆得到的整个 `prompt-optimizer` 目录放入宿主的技能目录。常见目录：Codex 的 `~/.agents/skills/`、Claude Code 的 `~/.claude/skills/`、WorkBuddy 的 `~/.workbuddy/skills/`；以宿主当前文档为准。保留 `references/` 和 `agents/`。已有同名技能时先检查版本，勿静默覆盖用户修改。新开会话或按宿主机制重新加载。

“本地 Skill”指本机上的指令文件，由当前 AI 使用；不要求本地模型，也不保证模型计算离线。此技能本身不需要浏览器、额外 API Key 或后台服务；宿主 AI 的模型与计费规则仍适用。

## 示例

```text
使用 $prompt-optimizer：帮我写一条研究提示词，比较三种笔记工具。
目标是 ChatGPT 网页端。只用公开资料，区分事实和判断，保留来源日期。
不要注册账号、购买产品或替我作个人选择。
```

```text
先评价，别改：
（粘贴待审阅提示词）
```

优化器默认返回一份可复制终稿，区分当前生效要求和用于核对的原始输入。目标结果的“只输出 JSON”不会被误当成优化器现在要输出业务 JSON。

可选要求：`+讲解`、`+提问`、`+双版`、`@目标=模型或环境`，不是使用前提。

## 与 Ego Lite、ChatGPT Pro 组合

完整组合包：[ego-pro-research](https://github.com/Samuel-Shek/ego-pro-research)。

流程：当前 AI 使用本优化器整理任务 → 当前 AI 审稿 → Ego Lite 中新建普通 ChatGPT 聊天 → 当前最高可用 Pro 研究 → 当前 AI 核验并交付原任务结果。

本优化器不依赖某个 GPTs 链接，也不负责操控浏览器。浏览器与 Pro 的依赖、访问和失败处理由研究协作 Skill 管理。
