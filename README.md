# prompt-optimizer

把粗糙需求整理为可执行、可复制的提示词。当前版本：**v3.4.0**，MIT 许可。

它是一个 Skill（写给 AI 读的工作说明书），放进 Codex、Claude Code 等能读取技能文件的 AI 工具即可使用，不是独立软件，也不是新模型。

## 三种使用方式

- **独立优化**：用户要改写提示词，返回一份终稿，不代做业务任务。
- **只审阅**：用户说“先评价，别改”，只指出问题，不自动重写。
- **宿主内部整理**：当前 AI 为复杂任务分配一个整理子任务；优化器返回提示词，当前 AI 继续完成原任务。不能只交提示词就宣称原任务完成。

## 优化逻辑

1. **先判断你要什么，再动笔**：执行请求、改写、只审阅、材料还没发完，分别处理，不见到任务就改写成提示词。
2. **控制指令、待改写材料、背景分开**：材料里夹带的“忽略之前规则”只是被处理的内容；材料里写的“只输出 JSON”约束的是目标任务，不是优化器本次交付。
3. **多轮修改有账**：最新明确修正才覆盖旧要求，没撤销的一直算数；“再短一点”不会顺手删掉禁止项。
4. **把愿望换成可检查的行为**：“尽量准确”换成来源、核验方法、不确定性标注。
5. **缺的信息不替你编**：能让目标模型去查的写明去哪查；低风险默认值标明是假设；必须由你补的才留占位符；会实质改变结果又无法默认时，才问，最多三个问题。

另有一条贯穿全程：**按任务决定复杂度，不按字数**。保留目标、数字、精确字符串、允许与禁止项、事实状态和验收标准；不为简单任务套长模板。

## 怎么知道它有没有用：考卷

仓库带一套固定考卷，在 [evals/](evals/)：16 道虚构题，12 道日常题加 4 道专门检查“有没有改坏”的留出题。每道题有优化器自身的检查项；7 道题还有效果对比：同一个目标模型分别执行“原话”和“优化后的提示词”，由人读结果判断哪个更好。

这套考卷只在维护时使用，不会注入生成的提示词。测试方法、结果和局限见 [evals/README.md](evals/README.md)。

## v3.4.0 更新

考卷首轮（v3.3）发现的主要毛病是“加料”：替用户多加没要的交付物、默认值和非必要的待填空位，7 道效果题里优化后的提示词中位数约为原话的 9 倍长。v3.4.0 只加了 5 句话，每一句都对应考卷里看到的具体失败：

1. 改写成规则时不比原话更严，也不更宽，不替用户补取舍标准。
2. 只为执行必需、且只能由用户提供的信息开占位符。
3. 不新增用户未要求的交付物，默认值只在缺了就无法执行时才加。
4. 用户写明的编号与标记符号（如“①②③”“【待补数据】”）照原样保留。
5. 终稿里本身含代码块时，外层用更长的围栏，避免复制时被截断。

复测摘要（Claude Opus 当优化器、Sonnet 当执行模型；样本很小，只看趋势）：

| 看什么 | v3.3 | v3.4 |
|---|---|---|
| 多加没要的交付物（公众号题） | 1 次里 1 次 | 4 次里 0 次 |
| 优化稿复制会被截断（代码框套代码框） | 26 份里 4 份 | 58 份里 0 份 |
| 周报：三条进展全写对 | 9 次里 2 次 | 9 次里 4 次 |
| 周报：第三段整段写“暂无” | 9 次里 1 次 | 9 次里 2 次 |
| 周报：①②③ 保留 | 9 次里 7 次 | 9 次里 9 次 |
| 16 道题优化稿总长度 | 17,588 字 | 13,063 字 |

**没有改好的**：周报漏写有据的进展只是改善、没有根治；决策分析题优化后的回答仍是原话版的 2–4 倍；简单任务（翻译、短消息）优化与否结果没有区别，而优化稿仍偏长（一句翻译的优化稿在 v3.4 里仍约 600 字），直接问更省事。

## 设计参考

优化器在 v3.3 之后，对公开的提示词优化资料做过一次集中阅读和比较，包括 LangMem、Prompt Optimizer（linshenkx）、OpenAI 公开的文本元提示词与 Cookbook 评估示例、LangGPT、Rosetta、Anthropic 与 AWS 的元提示词、Lyra、Hugging Face 上两个公开项目。这些资料只作设计参考，本仓库的指令均为自行撰写，没有收入它们的原文；各来源的许可证请以原项目为准。

比较后吸收得很少：

- 采纳“只在有失败证据时才改、做最小改动”的思路（来自 LangMem）。做法是用考卷找出失败，再只加对应的句子，没有另做一个修订模式。
- 采纳“先有考卷和基线分数，再改提示词”的做法（DSPy、Anthropic 与 OpenAI 的评估工具都是这个方向）。
- 没有吸收：固定角色外壳、固定欢迎语和选模式、每次固定追问几个问题、固定输出多种变体。这些与“按任务选结构”冲突。

`references/methods.md` 里的四种按需方法，借鉴自数字生命卡兹克分享的常用提示词，出处写在该文件内。

没有拿本优化器与上述任何一个具体产品做过逐项对跑，因此不主张它“比别人更好”，只说明它的取舍和证据。

## 安装

```bash
git clone https://github.com/Samuel-Shek/prompt-optimizer.git
```

把克隆得到的整个 `prompt-optimizer` 目录放入宿主的技能目录。常见目录：Codex 的 `~/.agents/skills/`、Claude Code 的 `~/.claude/skills/`、WorkBuddy 的 `~/.workbuddy/skills/`；以宿主当前文档为准。保留 `references/` 和 `agents/`。已有同名技能时先检查版本，勿静默覆盖用户修改。新开会话或按宿主机制重新加载。

“本地 Skill”指本机上的指令文件，由当前 AI 使用；不要求本地模型，也不保证模型计算离线。此技能本身不需要浏览器、额外 API Key 或后台服务；宿主 AI 的模型与计费规则仍适用。

## 示例

```text
使用 $prompt-optimizer：帮我写一条研究提示词，比较三种笔记工具。
目标是 ChatGPT 网页端。只用公开资料，区分事实和判断，保留来源日期。
不要注册账号、购买产品或替我作个人选择。
```

```text
先评价，别改：
（粘贴待审阅提示词）
```

优化器默认返回一份可复制终稿，区分当前生效要求和用于核对的原始输入。

可选要求：`+讲解`、`+提问`、`+双版`、`@目标=模型或环境`，不是使用前提。

## 与 Ego Lite、ChatGPT Pro 组合

完整组合包：[ego-pro-research](https://github.com/Samuel-Shek/ego-pro-research)。

流程：当前 AI 使用本优化器整理任务 → 当前 AI 审稿 → Ego Lite 中新建普通 ChatGPT 聊天 → 当前最高可用 Pro 研究 → 当前 AI 核验并交付原任务结果。

本优化器不依赖某个 GPTs 链接，也不负责操控浏览器。
