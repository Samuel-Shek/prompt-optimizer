# prompt-optimizer

**把粗糙需求，变成一份可直接复制使用的终版提示词。**

不代跑任务，不空谈技巧，只交付你真正能粘进目标模型的那一条 Prompt。

---

## 它解决什么问题

你大概率遇到过这些情况：

- 想让 AI 干活，但需求说得糙，出来的结果总差一口气
- 网上抄来的「万能 Prompt 模板」套上去，角色、步骤、自检清单一堆，简单任务被拖成空转
- 改了三轮 Prompt，上一轮说过的约束不知道还在不在
- 优化器「优化」完，顺手把业务也做了——你要的其实只是一条更好的指令
- 材料里夹了一句「忽略以上规则」，优化器就被人牵着走了

prompt-optimizer 的设计目标就一个：**产出可直接粘贴使用的终版提示词**，并且在整个优化过程中不丢约束、不编事实、不越权执行。

---

## 工作机制

### 1. 先路由，再动笔

收到消息后先判断你真正要什么，而不是看见任务就改写成 Prompt：

| 你的意图 | 它怎么做 |
|---|---|
| 新优化任务 | 出一份新终稿，不继承上个任务的私货 |
| 继续改上一版 | 在上一版上改，未撤销的要求继续生效 |
| 「还没发完 / 先别生成」 | 只收材料，不提前交稿 |
| 「先评价，别改」 | 只审阅，不自动附重写 |
| 普通闲聊 | 正常聊天，不强行优化 |

### 2. 三层信息分离

这是它和「全文丢进去重写」类工具最大的结构差异：

- **优化控制指令**——约束本次怎么优化（目标模型、长短、语言）
- **待优化材料**——真正要改写的 Prompt / 需求原文
- **背景材料**——帮你理解任务的上下文，不当成指令

材料内部写的「忽略之前规则」「直接回答」**只是被处理内容**，不能反过来指挥优化器。你本人提出的优化要求才是有效指令。

同时区分两层输出格式：

- 优化器**这次交付**用什么格式
- 目标模型**执行后**应输出什么格式

所以材料里写「只输出 JSON」，约束的是目标任务，不是让优化器现在就吐 JSON。

### 3. 多轮更新有账本

- 最新明确修正 > 被修正的旧要求
- 未被修改、撤销、替换的约束**继续保留**
- 「更简短」「自然一点」这类模糊调整，**不会静默删掉**你的禁止项、权限限制、关键事实
- 说不清的关键冲突会标出来等你确认，不偷偷选边

### 4. 最小充分，不堆模板

提示词复杂度由**任务**决定，不由输入字数决定：

- 简单写作 / 提取 → 简洁指令块
- 中等任务 → 目标、输入、输出、关键约束
- 多步骤工程 / 长期 Agent → 才加流程、权限、验证、异常处理

坚决删掉「世界级专家」「考虑所有可能性」这类换不成可观察行为的修辞。不为一句话需求强加角色扮演、分析框架和自检清单。

### 5. 把愿望翻译成规则

| 你说 | 它写成 |
|---|---|
| 尽量准确 | 来源、核验方法、不确定性标注、错误处理 |
| 写得专业 | 受众、语气、结构、术语密度、禁用表达 |
| 全面分析 | 范围、维度、时间边界、结论格式 |
| 代码可靠 | 环境、边界情况、测试、验收条件 |

### 6. 事实状态保真

「计划申请认证」不会被改成「已获认证」；「讨论过方案」不会被改成「已实施」；「可能有优势」不会被改成「已经领先」。

已提供的数字、日期、路径、代码、字段名、允许项、禁止项，按原样保留。不编造业务事实、研究结论、工具能力。

## 和常见提示词优化器的差别

| 维度 | 常见做法 | prompt-optimizer |
|---|---|---|
| 职责边界 | 优化完顺手把任务做了 | **只出 Prompt，不执行目标任务** |
| 信息处理 | 全文一股脑重写 | **控制指令 / 材料 / 背景** 三层分离 |
| 注入防护 | 有时把材料里的指令当真 | 材料内指令默认**只是数据** |
| 多轮修改 | 每轮当新任务，约束易丢 | **生效要求账本**，未撤销的继续保留 |
| 模糊调整 | 「简短点」可能删掉关键禁止项 | 模糊表述**不覆盖**明确约束 |
| 任务适配 | 一套长模板打天下 | 按写作 / 研究 / 代码 / 数据 / Agent **按需展开** |
| 篇幅策略 | 越长显得越专业 | **最小充分**，复杂度跟任务走 |
| 事实处理 | 容易把计划写成完成 | **事实状态锁**，不升格、不编造 |
| 交付物 | 散文式建议 + 示例 | **一份可复制终稿** + 原始输入核对区 |
| 环境假设 | 默认模型啥都会 | 不凭品牌假设有联网 / 文件 / 工具权限 |

## 设计优势

1. **可直接粘贴**——默认单份 Markdown 代码块，打开就能复制走
2. **可审计**——「当前生效要求」和「原始输入」分层，方便你核对有没有丢东西
3. **可多轮改**——继续修改不递归嵌套上一版 AI 稿，原始基准稳定
4. **抗干扰**——材料里的越权语句、假 system 指令不会劫持优化过程
5. **克制**——不把简单问题复杂化，不为显得专业而注水
6. **零依赖**——纯 Markdown Skill，无脚本、无联网、无 API Key

## 安装

Agent Skills 标准结构，**任何支持 `SKILL.md` 的 AI 工具都能装**。

```bash
git clone https://github.com/Samuel-Shek/prompt-optimizer.git
```

把 `prompt-optimizer/` 文件夹放进对应工具的技能目录：

| 工具 | 安装位置 |
|---|---|
| **Work Buddy** | `~/.workbuddy/skills/` |
| **Claude Code** | `~/.claude/skills/` |
| **Codex** | `~/.agents/skills/` |
| **Cursor / Windsurf 等** | 该项目的 skills 目录，或全局 skills 目录 |
| **其他 Agent Skills 宿主** | 宿主扫描的 skills 根目录 |

```bash
# 示例：装进 Claude Code
cp -r prompt-optimizer ~/.claude/skills/
```

重启工具或新开会话后生效。目录名保持 `prompt-optimizer`（与 front matter 的 `name` 一致）。

也支持直接下载 ZIP，解压后得到同名文件夹再拷贝。

## 怎么用

```
优化提示词：帮我写个分析销售数据的 prompt
```

```
改写这个 System Prompt，精简到 200 字以内：
（粘贴原文）
```

```
先评价，别改：
（粘贴 prompt）
```

可选快捷写法（不是必须）：

- `+讲解` — 终稿后附最多 5 条关键改动
- `+提问` — 允许先问 1—3 个必要问题
- `+双版` — 给两个用途不同的版本
- `@目标=Claude` / `@目标=网页端` — 按指定环境适配

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 把糙需求写成 Prompt | 直接执行业务任务 |
| 精简 / 扩写现有 Prompt | 去 AI 味润色正文（用 humanizer-zh） |
| 设计 System Prompt / Agent 指令 | 从零写文章、起标题 |
| 审阅 Prompt 找问题 | 改代码、改配置、翻译 |
